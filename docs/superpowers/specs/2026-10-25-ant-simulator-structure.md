- **Date:** 2026-10-25 (browser revision)
- **Companion to:** [the design spec](2026-10-25-ant-simulator-design.md). That document says *what* the simulator does; this one says *where* every piece lives and what it's called.
- **Rule for every plan and every agent:** don't rename or move anything listed here without updating this file in the same commit. Private helpers inside a module are free.
- **Status of the signatures:**
  - Milestone 0 signatures are final; the M0 plan builds exactly these.

## 2. Build, test and dependency rules

| Entry point | Runs in | Sources | May import |
|---|---|---|---|
| `dist/src/app/main.js` | Chrome | `app/main.ts`, `interactive.ts`, `headless.ts` | everything |
| `dist/src/app/bench_cli.js` | Node | `app/bench_cli.ts`, `bench.ts` | `core`, `sim`, `app/options`, `app/bench` |
| `node --test dist/tests` | Node | `tests/**/*.test.ts` | `core`, `sim`, `app` (pure parts) |
| `tools/serve.mjs` | Node | — | Node built-ins only |
| `tools/screenshot.mjs` | Node | — | Node built-ins only |

- **Layering is enforced by imports, not the type system.** `core` imports nothing. `sim` imports `core`. `app/options.ts`, `app/bench.ts` and the bench CLI import `core`/`sim` only. `render` imports `core`, `sim`, the DOM and WebGL. `ui` imports `core`/`sim` and the DOM. Only `src/app/main.ts` and its two mode modules may pull `render` and `ui` together.
- **`src/core` and `src/sim` never reference `document`, `window`, `canvas`, `WebGLRenderingContext` or `chrome`.** They must stay runnable by `node --test` and the bench CLI. There is no automated guard beyond this rule and the fact that Node runs them in tests.
- **No runtime npm dependencies.** Dev dependencies: `typescript` (exact pin) and `@types/node`.
- **`npm run build`** is `tsc -p tsconfig.json`; it emits `dist/src/...` and `dist/tests/...`.
- **Bundlers are banned.** Vite, esbuild, Rollup with native binaries and TypeScript 7's Go compiler are unsigned native programs that Smart App Control may block. `tsc` 5.9.3 is JavaScript and runs under Node.
- **Modules are native ES modules**; import specifiers end in `.js` in TypeScript source, so the emitted tree loads directly in Chrome and Node.

## 3. Conventions

- **Modules and types:** folders `core`, `sim`, `render`, `ui`, `app`; files `snake_case.ts`; types `PascalCase`; functions and variables `camelCase`; module-level constants `kPascalCase`.
- **Units:** world units (u), seconds, radians; **x points right and y points down**, so a positive angle turns clockwise on screen; heading 0 means +x.
- **Numbers:** `number` for simulation data. V8 uses doubles, so there is no float32/double distinction in source — but data stored in `Float32Array` is rounded to float32 and that is part of determinism.
- **Errors:** functions that can fail return `T | null` (or `{ ok: true } | { ok: false, error }`) and put a human-readable message in a string. No exceptions across module boundaries.
- **No global mutable state.** Everything hangs off `World`, the app loop, or an explicit object.
- **Comments** only where the code isn't self-explanatory.
- **Simulation data is plain data with free functions** (data-oriented), not class hierarchies.

**How `stepWorld` uses these, in order** (spec §5.2):
1. `applyPendingEdits` [M2]
2. `SpatialHash.build` [M2]
3. Think: chunks of `chunkSize` ants [M1]
4. `applyEvents` [M1]
5. Collisions: `resolveWallCollisions` [M2], then `resolveAntOverlaps` [M4]
6. `removeDead` [M1]
7. `decayMarkers` [M1]
8. `updateStats` [M1]

Each phase is timed into `World.timings`. Legs are **not** part of `stepWorld`; the app updates them once per frame.

## 5. Who writes what in each phase

| Phase | Runs | Reads | Writes |
|---|---|---|---|
| Edits | serial | `pendingEdits` | obstacles, markers, food, colonies, trapped ants |
| Spatial hash | serial | ant positions | `hash` |
| Think | parallel, chunks of `chunkSize` | anything | only its own ants' fields, and its own `chunkEvents[chunk]` |
| Events | serial, in chunk order | `chunkEvents` | markers, food, colonies, contacted ants, new ants (appended) |
| Collisions | parallel (Jacobi into scratch), then apply | positions, hash, obstacles | own ants' `pos`/`vel` |
| Removals | serial, descending index | `energy` | ants (swap-and-pop), uid map, populations |
| Decay | parallel by grid rows | markers | own rows of markers |
| Stats | serial | colonies | colony stats |
| Legs (per frame, outside `stepWorld`) | parallel | ants, camera view | leg fields of visible ants |

Determinism follows from this table. If something has to write outside its own slot, it emits an event instead. Browser workers (M4) preserve the same chunking, so results do not depend on the worker count.

### Task outlines for M1–M6

**M1 — Core foraging, one colony**
1. Add the `RandStream` values and `RingBuffer`, with tests.
2. Ants SoA over typed arrays: spawn, swap-remove and the uid map. Tests keep the uid map consistent across 1,000 random spawns and removals.
3. MarkerGrid: deposit (own-cell rule), emission, decay factor and the decay pass. Tests: the factor at dt = 1/60 equals 0.9985 ± 2e-5; values below `markerEps` reset the owner.
4. Food sources and colony: radius, `takeOne`, nest radius and the spawn cost. Tests.

## 7. Changes against the design spec

- **The project is a browser TypeScript app** (2026-10-25 pivot). The C++/SDL3/ImGui version is archived on branch `archive/cpp-m0`; no native programs are built or run because Smart App Control blocks unsigned executables.
- The spatial hash moves from M4 to **M2**, because M2's stuck rule needs neighbour counts.
- **Home** refits the camera to the world.
- Bench prints both ticks per second and ant updates per second.
- Workers (the "thread pool") move from M0 to **M4**; M0–M3 are single-threaded and deterministic by construction.
