### Task 2: Speed (target ≤ 6 ms), measured after each change
Likely wins; do them in the order the profile says, one commit each, re-bench each:
1. **Early-outs.** An ant with no other ant in its own and the 8 neighbouring hash cells skips avoidance and PBD entirely (a cell-count check, no per-pair work). Most ants in open ground are alone.
2. **Cheaper queries.** Avoid `Math.sqrt` unless an overlap is confirmed (compare squared distances first); shrink the PBD query radius to `2·antRadius` plus a small margin; reuse the hash built for avoidance in the PBD pass if positions have moved less than a cell (or measure rebuilding vs reusing).
3. **Avoidance cost.** It is already time-sliced by `uid` parity; check that the slicing really halves the work, and that `maxNeighbours` (16) and `rAvoidMax` (24) are the cheapest values that keep lanes/overlap. Try 12 and 8 neighbours and record the effect.
4. **Memory.** Make sure scratch arrays are reused and typed; no object or array allocation inside the per-ant loops.
- **Order independence and the legacy checksum must stay intact** after every change.
- Stop this task when the median ≤ 6 ms, or when the log shows no further gain; in the latter case say so plainly in the report.
- Commit each: `perf(sim): <what>`

### Task 3: Lane tie-break (target lanes ≥ 0.70)
Background from the report: the current sidestep pushes each ant *away* from the other, which is mirror-symmetric, so off-axis pairs repel instead of settling into lanes. Own-right everywhere gave lanes 0.562 but overlap 0.105; own-right for near-head-on pairs only gave 0.570 / 0.121. So a pure "everyone goes right" rule creates crowding. Aim for a rule where **both ants of a pair agree on who goes where**, so they swap sides cleanly.

Experiments, in this order, each logged:
1. **Pair tie-break by uid.** For a pair that will meet, compute the lateral miss as now. If the pair is near head-on (|lateral miss| below a threshold, try 0.5·`antRadius`), decide the side from the pair, not from each ant: both ants step to *their own right* (this is consistent for true head-on), but when the pair is not near head-on keep "away from the other". Where the lateral miss is ~0 and the headings are nearly equal (same-direction followers), use the lower uid to pick which side the *other* ant moves to, so they do not both dodge the same way.
2. **Lane keeping.** A weak steady bias toward the right-hand side of the ant's own heading when it has opposing traffic in its cone, strength well below the avoidance push (start at 10–20% of `avoidMaxSpeedFactor`). This is what stabilises lanes after the first pass.
3. **Hysteresis.** Once an ant has picked a side for a neighbour, keep it for about 0.5 s (store the side in a scratch/Avoid array indexed by slot, cleared on swap-and-pop; remember these arrays are in the checksum only when collisions are on).
4. Try thresholds (0.25, 0.5, 1.0 × `antRadius`) and strengths on a **small grid, logging each row as it completes**. Seed 1 first; confirm the winner on seeds 2 and 3, because lanes is a statistical metric.
- Keep the own-right rule from the previous commits reachable behind the existing parameter so the comparison stays reproducible.
- **Tests:** a head-on pair at an exact tie still resolves, in both orders of uid and in both array orders, to the same positions (order independence); a pair with equal headings does not both dodge the same way; the 2000-ant crowd gives lanes strictly above the current 0.466 (use a smaller, faster crowd for the unit test).
- Commit: `feat(sim): pair-consistent sidestep and lane keeping`

### Task 4: Food-queue exemption (target reach 1500 u ≥ 63)
Hypothesis (untested): ants queueing at a food source and at their nest block each other, which lowers deliveries at long range (1500 u: 84 before M4, 51 after). The nest already has `nestExemptFactor`.
- Add the same exemption around food sources an ant is targeting: within `foodRadius × foodExemptFactor` of a source it can pick up from, the ant is exempt from the PBD ant pass and from avoidance (keep wall resolution). Add `foodExemptFactor` to params, default 1.0, a settings row only if the other M4 rows have one.
- First measure whether this helps at all: `npm run reach` at factor 1.0, 1.5, 2.0 and log minute-3 deliveries for 500/1000/1500/2000 and the contest.
- Also re-test `nestExemptFactor` 1.5 together with it (earlier alone: overlap 0.022, lanes 0.452, no throughput data).
- **Keep it only if** 1500 u m3 rises toward 63 **and** crowd overlap does not get worse. Otherwise remove it and log why.
- Commit: `feat(sim): food and nest queue exemption` (or `docs: queue exemption tried, not adopted` if dropped).

### Task 5: PBD iterations (target overlap ≤ 1%)
