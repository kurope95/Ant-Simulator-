# M4.5 multi-core: plan (2026-10-31)

Marek, 2026-10-31: "we need a multi-processor-core run definitely as the next step". With 2,000+ ants a step takes 8–30 ms on one core, so the game cannot run at 1×, whatever speed is chosen. Spec §15 M4.5 sets the goal: a worker pool over SharedArrayBuffer typed arrays, cross-origin isolation, determinism with 1 and N workers.

Work on `main`, push after each finished piece, then merge into `fight` (Marek's workflow).

## Step 1: the ants' thinking on all cores
Think (`thinkChunk`) is 60–70% of a step and every ant thinks independently: it writes only its own slots and its chunk's event list (spec §5.2).

1. **Shared memory.** `core/shared.ts` allocates typed arrays on a `SharedArrayBuffer` when one is available (Node always; Chrome/Edge when the page is cross-origin isolated, which `tools/serve.mjs` already arranges). Ants (including growth), marker layers, obstacle grid and spatial hash use it. Same speed as ordinary typed arrays.
2. **Start-of-step positions.** The crowd count in Think (stuck detection, patience at food) read other ants' live positions, so its answer depended on chunk order. At the start of each step `prevX/prevY` are set to the positions for every ant, and those counts read `prevX/prevY`. This changes results by rounding-level amounts, so the legacy checksum is re-recorded.
3. **Phases split.** `stepWorld` = `stepBeforeThink` + think + `stepAfterThink`; avoidance (and on `fight`, the look-around) stays on the main thread in `stepBeforeThink`.
4. **Mirror world.** `sim/parallel.ts`: `shareWorld(world)` builds a per-step message: shared buffer references (no copying), counts, the tick, params, and the small plain data (food items, colonies). `mirrorWorld(message)` in a worker builds a `World` whose arrays are views on the same memory. `thinkRange` runs `thinkChunk` over a worker's chunks and encodes each chunk's events as a flat `Float64Array`; `decodeChunkEvents` turns them back into `ChunkEvents` in chunk order on the main thread.
5. **Pools.** Browser: `app/worker_pool.ts` with module workers (`app/think_worker.ts`), `navigator.hardwareConcurrency − 1` workers, at most 7. Node (tests, bench): the same protocol over `worker_threads` (`tools/`/`tests/` glue only; `src/sim` stays free of environment APIs).
6. **Game loop.** `stepWorldParallel(world, pool)` is async; the controller awaits it inside its per-frame step budget and never starts a frame's stepping while one is in flight. Without a pool (no shared memory, or one core) it runs `stepWorld` as now.
7. **Tests.** Same checksum after 600 ticks of a multi-colony preset with `stepWorld` and with 1, 2 and 4 workers.
8. **Measure.** `npm run bench`-style timing of a 2,000-ant step, serial against the pool, plugged in if possible.
