**Goal:** A native ARM64 Windows app that opens a sharp, DPI-aware window. A camera-controlled test pattern, driven by a fixed 60 Hz simulation clock, sits under a correctly scaled ImGui debug panel. Alongside that come headless PNG screenshots, a bench mode, a thread pool, a deterministic random-number generator and a unit-test suite. There are no ants yet.

**Architecture:**
- Five static libraries and one console executable (`AntSim`), layered `core → sim → appcore` and `sim → render → ui`.
- `core`, `sim` and `appcore` never touch SDL or ImGui, so they can be tested and benchmarked without a window.
- `render` draws through SDL3's Direct3D 11 renderer using batched `SDL_RenderGeometry` calls. `ui` wraps Dear ImGui.
- `AntSim` has three modes: interactive, headless and bench.

**Tech Stack:** C++20, MSVC 14.51 (Visual Studio Build Tools 2026), CMake 4.4 with presets, SDL3 3.4.18, Dear ImGui 1.93.0, doctest 2.5.3, stb_image_write.

**Spec:**
- `docs/superpowers/specs/2026-10-25-ant-simulator-design.md` (*what*: this plan implements row M0 of §15),
- `docs/superpowers/specs/2026-10-25-ant-simulator-structure.md` (*where*, and every name).

## Global Constraints

- **Platform:** Windows 11 ARM64 only. Compiler: MSVC from Visual Studio Build Tools 2026 (toolset 14.51). Configure only with `cmake --preset arm64` (generator `Visual Studio 18 2026`, `-A ARM64`).
- **CMake:** at least 3.28 (4.4.4 is installed); `CMakePresets.json` version 6.
- **Language:** C++20, no compiler extensions.
- **Flags on our targets:** `/W4 /permissive- /utf-8 /Zc:__cplusplus /external:anglebrackets /external:W0`, plus `/WX` while `ANTSIM_WARNINGS_AS_ERRORS` is ON (the default). Never use `/fp:fast`.
- **Dependencies,** fetched with FetchContent and built from source only:
  - SDL3 `release-3.4.18`
  - Dear ImGui `v1.93.0`
  - doctest `v2.5.3`
  - stb `003501f6d7a8668ce8b6d875e34dd97ad0d5d5b5`

  No vcpkg, conan or prebuilt binaries.
- **Graphics:** the SDL renderer must come up as `direct3d11` (fallback `direct3d12`). No OpenGL-only libraries.
- **Layering:** `src/core`, `src/sim`, `src/app/options.*` and `src/app/bench.*` must not include SDL or ImGui headers.
- **Randomness:** only through `core/rng.hpp`. Never `rand()`, `std::random_device` or `<random>` engines.
- **Build folder:** `<repo>/build`, never under `%TEMP%`. Outputs are `build/<Config>/AntSim.exe` and `build/<Config>/antsim_tests.exe`.
- **Naming:**
  - namespaces `antsim::core|sim|render|ui|app`;
  - files `snake_case.hpp/.cpp`;
  - types `PascalCase`; functions and variables `snake_case`; constants `kPascalCase`;
  - private members end with `_`.
- **Includes:** own headers with quotes, relative to `src/`. Third-party headers with angle brackets.
- **Coordinates:**
  - x points right and **y points down**;
  - angles are in radians, and a positive angle turns clockwise on screen;
  - heading 0 means +x.
- **Exit codes:** 0 success, 1 runtime failure, 2 usage error.
- **Commits:** after every task, with the message given. Never commit `build/`.
- **Checked before handover:** the plan's CMake files, dependency pins, ImGui 1.93.0 scaling API, RNG golden values, fixed-step numbers and bench-format spacing were compiled and run on this laptop on 2026-10-25.
- **Doubtful API calls:** if an SDL3 or ImGui call in this plan doesn't compile, look at the exact versions you fetched:
  - `build/_deps/sdl3-src/include/SDL3/`
  - `build/_deps/imgui-src/examples/example_sdl3_sdlrenderer3/main.cpp`

## Review Focus

These are the failure modes most likely to hit a real user that ordinary tests wouldn't reach, and the test that pins each one:

1. **Minimised window (0×0 viewport).** Expected: no crash and no NaN coordinates. Pinned by Task 9 "zero-size viewport"; Task 13 also skips drawing while minimised.
2. **Paths with spaces or non-ASCII characters, or a missing folder.** The project path itself contains spaces. Expected: the screenshot is still written. Pinned by Task 11 "new folder with spaces and non-ASCII" and Task 12's CTest, which writes inside this repo.
3. **Long stalls.** Windows freezes the loop while you drag or resize the window, and so does a debugger. Expected: no burst of fast-forward afterwards. Pinned by Task 5 "long stall is capped".
4. **Bad command-line input.** Expected: a specific error message, the usage text, and exit code 2. Pinned by Task 7 "errors are specific" and the Task 8 manual check.
5. **Thread counts other than 8** (1, 3, 16). Expected: identical chunking and bit-identical sums. Pinned by Task 4.

- [ ] **Step 3: Implement `src/core/rng.hpp` with exactly this algorithm.** The golden values above depend on it.

```cpp
inline std::uint64_t mix64(std::uint64_t z) {   // SplitMix64 finalizer
    z = (z ^ (z >> 30)) * 0xBF58476D1CE4E5B9ull;
    z = (z ^ (z >> 27)) * 0x94D049BB133111EBull;
    return z ^ (z >> 31);
}
inline std::uint32_t rand_u32(std::uint64_t seed, std::uint32_t uid, std::uint64_t tick, std::uint32_t stream) {
    std::uint64_t h = mix64(seed + 0x9E3779B97F4A7C15ull);
    h = mix64(h ^ ((std::uint64_t{uid} << 32) | stream));
    h = mix64(h ^ tick);
    return static_cast<std::uint32_t>(h >> 32);
}
// rand_unit  = static_cast<float>(rand_u32(...) >> 8) * (1.0f / 16777216.0f)   (24 bits, so always < 1)
// rand_range = lo + (hi - lo) * rand_unit(...)
```

- [ ] **Step 3: Implement `ThreadPool`, and add `core/thread_pool.cpp` to `antsim_core`.** The tests don't determine the design, so follow this one:
  - **Workers:** `thread_count - 1` persistent `std::jthread`s that sleep on a condition variable until the *job generation* changes.
  - **Inline fast path:** with `count == 0`, return. With one thread or one chunk, run every chunk on the caller, in order.
  - **Publishing a job:** under the mutex, store `&fn`, `count`, `chunk_size`, `chunks`; reset an atomic `next_chunk = 0` and `remaining = chunks`; bump the generation; `notify_all`.
  - **Doing the work:** the caller and the workers each run `drain()`. It claims chunk indices with `next_chunk.fetch_add(1)` until the index is ≥ `chunks`, and runs `fn(i, i*chunk_size, min((i+1)*chunk_size, count))`.
  - **Returning:** `parallel_for` returns only when `remaining == 0` **and** no worker is still inside `drain()`. Track a busy-worker count, changed under the mutex. Otherwise the next call could reset the job while a slow worker still holds the old one.
  - **Shutdown:** the destructor sets `stopping`, calls `notify_all`, and the `jthread`s join.
  - **Nesting:** `parallel_for` is not re-entrant. Calling it from inside `fn` is a bug; `assert` against it.

- [ ] **Step 3: Implement it with this algorithm.** The epsilon matters, because 1/120 + 1/120 is not exactly 1/60 in floating point.

```text
advance(frame, speed):
    if speed <= 0: return 0
    acc += max(frame, 0) * speed
    n = 0
    while acc + 1e-9 >= step and n < max_steps: acc -= step; n += 1
    if n == max_steps and acc >= step: acc = fmod(acc, step)      # drop the backlog
    acc = max(acc, 0)
    return n
alpha() = min(acc / step, 0.999999)
```

- [ ] **Step 4: Implement `run_interactive`, in this order**
  1. **Session:** open a visible, maximized session with `vsync = options.vsync`. Print `build_info()`, `renderer: <driver>`, `display scale: <s, 2 decimals>` and `threads: <n>`.
  2. **Set up:** `imgui.init(...)`, `World world = make_world(SimParams{}, options.seed)`, `ThreadPool pool(options.threads)`, `Camera` (viewport = `renderer.output_size()`, then `fit(world.size)`), `FixedStepClock clock(1.0 / sim_hz, 16)`. State: `paused`, `step_requests`, `zen`, `dragging`.
  3. **Each frame, poll every event.** Call `imgui.process_event(e)` first, then:
     - `SDL_EVENT_QUIT` or `SDL_EVENT_WINDOW_CLOSE_REQUESTED` leaves the loop.
     - `SDL_EVENT_WINDOW_PIXEL_SIZE_CHANGED` calls `camera.set_viewport(renderer.output_size())`.
     - `SDL_EVENT_WINDOW_DISPLAY_SCALE_CHANGED` calls `imgui.set_display_scale(SDL_GetWindowDisplayScale(window))`.
     - When `!imgui.wants_mouse()`:
       - the wheel calls `camera.zoom_at(mouse position × SDL_GetWindowPixelDensity(window), pow(1.15, wheel.y))`;
       - right or middle button down/up sets or clears `dragging`;
       - motion while dragging calls `camera.pan_by_screen({xrel, yrel} × pixel density)`.
     - When `!imgui.wants_keyboard()`, on key down without repeat:
       - **P** toggles `paused`;
       - **Space** increments `step_requests` while paused;
       - **H** toggles `zen`;
       - **Home** calls `camera.fit(world.size)`.
  4. **Minimised:** if the window is minimised, `SDL_Delay(16)` and skip the rest of the frame.
  5. **Simulate:** `steps = clock.advance(frame_seconds, paused ? 0.0 : 1.0) + step_requests`, then reset `step_requests`. Run `step_world` that many times.
  6. **Draw:**
     1. `renderer.clear(sand_theme().outside)`;
     2. build the test pattern with `sim_seconds = (tick + (paused ? 0 : alpha)) / sim_hz` and draw it;
     3. `imgui.new_frame()`; unless `zen`, call `draw_debug_panel(...)` (fps from `ImGui::GetIO().Framerate`); then `imgui.render(...)`;
     4. `renderer.present()`.
  7. **After the loop:** `imgui.shutdown()`, return 0.
