## Deviations from the plan

- **Task 3:** the plan asked to extract the sample pattern. `followerPattern` and `explorerPattern` already exist in `sim/sensing.ts`, so `sensorView` reuses them and no refactor was needed. The one real change is splitting `directSightHeading` into `directSightTarget` (returns the point) and the angle; that gives the inspector the target point. The result is identical (the golden checksum confirms it). `senseChannel` in `sim/tick.ts` is now exported so the sensor view uses the same channel rule.
- **Task 1:** names use a 64-name list with a coprime multiplier per block of 64 uids, not a plain hash. This keeps the first 64 uids distinct, which the plan's "at least 900 of the first 1000" test needs.
- **Task 2:** `pickAnt` takes the radius in world units as the plan says. The controller passes 12 CSS px divided by the camera scale.
- **Task 6:** the sparklines are redrawn at most every 500 ms; the inspector text updates each frame, which the plan did not forbid. The panel shares the right-hand slot with the settings drawer (a new `inspectorHost` in `RunHud`), not a new screen.
- **Task 8:** a wheel pan cancels follow by using `classifyWheel(event, -Infinity)`. This ignores the 250 ms pan-hold window, so a notch that arrives right after a touchpad pan can still count as a pan. Wheel zoom keeps follow. Pressing A on Run does not cancel follow, since it toggles ants.
- **Task 10:** `--inspect`, `--follow` and `--sensors` are applied through the controller, so they work with `--interactive --screen run` (or the page URL), not in headless mode. The headless path draws the world without the controller, so it has no selection or overlay.
- **Task 9:** the range 0.5–10 s comes from the M1 plan's table; the design spec gives only the default (3.0 s).
